# Comando naibi e strumenti per gli agenti IA

Il comando `naibi` permette a un agente IA (Claude Code, Codex, Cursor…) o a uno script di lavorare su un progetto senza aprire l'app: legge i dati, segnala i problemi e disegna le carte in PNG. È lo stesso programma dell'app avviato con `--cli`: nessuna finestra, stesso rendering delle esportazioni.

## Comandi

| Comando                                                                                                | Cosa fa                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `info <progetto>`                                                                                      | set, template e livelli, variabili, stili, asset, profili di esportazione                                                                                                                                                                                                                            |
| `check <progetto> [--set S]`                                                                           | problemi di ogni carta (immagini o font mancanti, variabili sconosciute, errori di markup e formule) e, senza `--set`, dei documenti; esce con 1 se ce ne sono                                                                                                                                       |
| `check-data <progetto>`                                                                                | come viene letto il file dei dati: per ogni foglio i set che lo usano, le colonne che i loro template leggono e il foglio non ha, e le anomalie (titolo sopra le intestazioni, righe vuote, celle unite, errori, formule senza risultato); è lo stesso controllo di **Controlla file dati** nell'app |
| `template <progetto> <nome>`                                                                           | livelli del template (per un derivato, già risolti, con il base e le differenze); con `--json` il template completo                                                                                                                                                                                  |
| `rows <progetto> <set> [--json\|--csv]`                                                                | righe del set, separate da tab se non si indica altro                                                                                                                                                                                                                                                |
| `set-rows <progetto> <set> <file.json\|file.csv>`                                                      | sostituisce le righe del set, dopo aver fatto un backup del progetto                                                                                                                                                                                                                                 |
| `pull-sheets <progetto> [<link>]`                                                                      | sostituisce i dati dei set con le schede con lo stesso nome di un foglio Google condiviso con il link (senza link usa quello salvato nel progetto; un link nuovo si salva), dopo aver fatto un backup del progetto                                                                                   |
| `rename-set <progetto> <set> <nome>`                                                                   | rinomina il set, il suo foglio nel file dei dati e i profili di esportazione che lo scelgono, dopo un backup                                                                                                                                                                                         |
| `rename-template <progetto> <template> <nome>`                                                         | rinomina il template e il suo file; set, derivati e colonna `template` delle carte seguono il nome nuovo; prima fa un backup                                                                                                                                                                         |
| `render <progetto> [--set S] [--card 1,3,5-7] [--side front\|back\|both] [--dpi 150] [--out cartella]` | disegna le carte in PNG, di base in `export/naibi-render/<set>/<n>.png`                                                                                                                                                                                                                              |
| `export <progetto> --profile NOME`                                                                     | esegue un profilo di esportazione salvato nel progetto                                                                                                                                                                                                                                               |
| `new <nome> <cartella>`                                                                                | crea un progetto vuoto                                                                                                                                                                                                                                                                               |
| `notes <progetto> [<nome>]`                                                                            | note del progetto (`notes/*.md`), tutte o una; l'agente le scrive come file Markdown in `notes/`                                                                                                                                                                                                     |
| `docs <progetto> [<nome>]`                                                                             | documenti del progetto (`docs/*.md`: regolamento, sell sheet, appendici), tutti o uno, con i loro problemi (carte o immagini che non si trovano); l'agente li scrive come file Markdown in `docs/`                                                                                                   |
| `stats <progetto> <set> [--column C]`                                                                  | quante carte hanno ogni valore di ogni colonna (o di una), con somma, media, minimo e massimo delle colonne numeriche                                                                                                                                                                                |
| `begin <progetto> [--note testo]`                                                                      | inizio del lavoro di un'IA: esce con 3 se l'app ha modifiche non salvate nel progetto, altrimenti l'app si blocca                                                                                                                                                                                    |
| `end <progetto>`                                                                                       | fine del lavoro: l'app si sblocca e ricarica il progetto                                                                                                                                                                                                                                             |

`info`, `check`, `template`, `stats`, `notes` e `docs` accettano `--json`. `naibi --help` elenca i comandi.

## Come si lancia

- App installata: `"<percorso del programma>" --cli <comando>`. Su Mac il programma è dentro il pacchetto, per esempio `"/Applications/Naibi.app/Contents/MacOS/Naibi" --cli info ~/Documents/Naibi/Prova`.
- Su Windows, con l'app installata, si usa `naibi-cli.cmd`, che sta accanto a `naibi.exe` (di solito in `%LOCALAPPDATA%\Programs\naibi`): per esempio `& "$env:LOCALAPPDATA\Programs\naibi\naibi-cli.cmd" info "D:\Giochi\Prova"` in PowerShell. `naibi.exe` è un programma a finestre: lanciato direttamente il terminale non ne aspetta la fine, l'output arriva dopo il prompt e il codice di uscita si perde. Il file `.cmd` aspetta, restituisce il codice e avvia Chromium senza la sua sandbox, che non parte dentro quella di alcuni agenti IA (Codex). **Strumenti IA…** nell'app mostra già questo comando. La versione portable non ha il file `.cmd`.
- Codex su Windows esegue i comandi in una sandbox che legge solo le cartelle aperte alle app in sandbox. Dalla 1.2.0-beta.9 l'installer apre la cartella di Naibi in sola lettura ed esecuzione, quindi non serve fare niente. Con una versione precedente, o se compare ancora l'errore _Sandboxed processes cannot read …_, si approva l'esecuzione fuori dalla sandbox quando Codex la chiede, oppure si dà il permesso a mano, da una PowerShell normale: `icacls "$env:LOCALAPPDATA\Programs\naibi" /grant "*S-1-15-2-1:(OI)(CI)(RX)" /T` (`*S-1-15-2-1` è il gruppo ALL APPLICATION PACKAGES, con un nome diverso nelle versioni tradotte di Windows).
- Dal codice: una volta `npm run build`, poi `npm run naibi -- info <progetto>` oppure `node bin/naibi.mjs info <progetto>`. Con `npm link` il comando diventa `naibi` in ogni cartella.

## Lavorare con l'app aperta

L'app e un agente non devono modificare lo stesso progetto insieme, altrimenti un salvataggio dell'uno cancella le modifiche dell'altro. Per questo l'agente apre e chiude il suo lavoro con `begin` ed `end`, come chiede la skill:

- l'app aperta scrive nella cartella del progetto il file `.naibi-app`, con il suo processo e se ha modifiche non salvate;
- `begin` rifiuta di partire (codice di uscita 3) se l'app ha modifiche non salvate: l'agente chiede di salvare e si ferma. Altrimenti scrive il file `.naibi-ai`;
- finché c'è `.naibi-ai` l'app mostra un avviso e non si usa. Si controlla ogni secondo;
- `end` cancella `.naibi-ai`: l'app si sblocca e ricarica il progetto da sola.

Se l'agente si ferma senza `end`, nell'avviso c'è **Sblocca ora**. `set-rows`, `pull-sheets`, `rename-set` e `rename-template` rifiutano anche da soli (codice di uscita 2) se l'app ha modifiche non salvate, e anche se l'app è aperta sul progetto senza che sia stato fatto `begin`: altrimenti il prossimo salvataggio dell'app cancellerebbe le loro modifiche. I due file iniziano con il punto, quindi restano fuori dai backup; un `.naibi-app` lasciato da un'app chiusa male non conta, perché il suo processo non c'è più. Su un disco condiviso tra più computer il file dell'app conta solo se è stato aggiornato negli ultimi 5 minuti (l'app lo riscrive ogni 30 secondi).

Se in `naibi.json` c'è `"dataReadOnly": true` (il file dei dati in sola lettura, impostato nell'app), `set-rows` e `pull-sheets` rifiutano, e `rename-set` rinomina il set ma non il foglio.

Il backup fatto da `set-rows`, `pull-sheets`, `rename-set` e `rename-template` va nella stessa cartella dei backup automatici dell'app, con le stesse impostazioni (cartella e numero di backup da tenere).

## Skill per gli agenti

La skill è in [skill/naibi/SKILL.md](../skill/naibi/SKILL.md), in inglese: spiega il formato del progetto, il markup, le formule e il modo di lavorare (`info`, poi le modifiche, poi `check` e `render` per controllare). Il segnaposto `{{NAIBI_COMMAND}}` indica come lanciare il comando.

Nell'app il pulsante **Strumenti IA…** (schermata di ingresso e barra in alto) mostra la skill con il comando di questo computer già inserito. Si può copiare e incollare nell'agente, chiedendogli di installarla, oppure salvare come file in `<cartella>/naibi/SKILL.md`; Claude Code legge le skill da `~/.claude/skills` o da `.claude/skills` dentro un progetto. Solo le istruzioni intorno alla skill sono tradotte.

Quando cambia il formato del progetto va aggiornata anche la skill.
