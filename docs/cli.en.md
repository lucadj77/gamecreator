# The stella command and the tools for AI agents

_Italiano: [cli.md](cli.md)._

The `stella` command lets an AI agent (Claude Code, Codex, Cursor…) or a script work on a project without opening the app: it reads the data, reports problems and draws the cards as PNG. It is the same program as the app, started with `--cli`: no window, the same rendering as the exports.

## Commands

| Command                                                                                                        | What it does                                                                                                                                                                                                                                                                                                                                                             |
| -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `info <project>`                                                                                               | sets, templates and layers, variables, styles, assets, export profiles                                                                                                                                                                                                                                                                                                   |
| `check <project> [--set S] [--lang L]`                                                                         | problems of every card (missing images or fonts, unknown variables, markup and formula errors) and, without `--set`, of the documents; exits with 1 if there are any. Also lists untranslated texts as warnings, which do not change the exit code: in L or, without `--lang`, in every language besides the main one; with `--lang` it binds the cards in that language |
| `check-data <project>`                                                                                         | how the data file is read: for each sheet the sets that use it, the columns their templates read and the sheet lacks, and the anomalies (a title above the headers, empty rows, merged cells, errors, formulas without a result); the same check as **Check data file** in the app                                                                                       |
| `template <project> <name>`                                                                                    | the layers of the template (for a derived one, already resolved, with the base and the differences); with `--json` the whole template                                                                                                                                                                                                                                    |
| `rows <project> <set> [--json\|--csv]`                                                                         | the rows of the set, tab-separated unless told otherwise                                                                                                                                                                                                                                                                                                                 |
| `set-rows <project> <set> <file.json\|file.csv>`                                                               | replaces the rows of the set, after a backup of the project                                                                                                                                                                                                                                                                                                              |
| `pull-sheets <project> [<link>]`                                                                               | replaces the data of the sets with the sheets of the same name of a Google spreadsheet shared by link (without a link it uses the one saved in the project; a new link is saved), after a backup of the project                                                                                                                                                          |
| `rename-set <project> <set> <name>`                                                                            | renames the set, its sheet in the data file and the export profiles that pick it, after a backup                                                                                                                                                                                                                                                                         |
| `rename-template <project> <template> <name>`                                                                  | renames the template and its file; sets, derived templates and the `template` column of the cards follow the new name; a backup comes first                                                                                                                                                                                                                              |
| `render <project> [--set S] [--card 1,3,5-7] [--side front\|back\|both] [--dpi 150] [--out folder] [--lang L]` | draws the cards as PNG, by default in `export/stella-render/<set>/<n>.png`; with `--lang` one language of the project, in `export/stella-render/<language>/`                                                                                                                                                                                                             |
| `export <project> --profile NAME [--lang L\|all]`                                                              | runs an export profile saved in the project; `--lang` picks a language (the other languages go in the subfolder with their code) or `all` for every language                                                                                                                                                                                                             |
| `new <name> <folder>`                                                                                          | creates an empty project                                                                                                                                                                                                                                                                                                                                                 |
| `notes <project> [<name>]`                                                                                     | the notes of the project (`notes/*.md`), all or one; the agent writes them as Markdown files in `notes/`                                                                                                                                                                                                                                                                 |
| `docs <project> [<name>]`                                                                                      | the documents of the project (`docs/*.md`: rulebook, sell sheet, appendices), all or one, with their problems (cards or images that cannot be found); the agent writes them as Markdown files in `docs/`                                                                                                                                                                 |
| `export-doc <project> [<name>] [--format pdf\|html\|docx\|md] [--out folder] [--lang L]`                       | exports the documents, all or one, like **Export document…** in the app: PDF (default), self-contained HTML, Word (`.docx`) or Markdown with the cards as PNG, by default in `export/docs/`; warns about references that cannot be found; `--lang` draws the cards in that language instead of the document's `language`                                                 |
| `stats <project> <set> [--column C]`                                                                           | how many cards have each value of each column (or of one), with sum, average, minimum and maximum of the numeric columns                                                                                                                                                                                                                                                 |
| `begin <project> [--note text]`                                                                                | start of an AI's work: exits with 3 if the app has unsaved changes in the project, otherwise the app locks                                                                                                                                                                                                                                                               |
| `end <project>`                                                                                                | end of the work: the app unlocks and reloads the project                                                                                                                                                                                                                                                                                                                 |
| `version`                                                                                                      | the version of the command (also `--version`): the skill compares it with its own and with the latest release                                                                                                                                                                                                                                                            |

`info`, `check`, `template`, `stats`, `notes` and `docs` accept `--json`. `stella --help` lists the commands.

## How to run it

- Installed app: `"<path of the program>" --cli <command>`. On Mac the program is inside the bundle, for example `"/Applications/Stella.app/Contents/MacOS/Stella" --cli info ~/Documents/Stella/Test`.
- On Windows, with the installed app, use `stella-cli.cmd`, next to `stella.exe` (usually in `%LOCALAPPDATA%\Programs\stella`): for example `& "$env:LOCALAPPDATA\Programs\stella\stella-cli.cmd" info "D:\Games\Test"` in PowerShell. `stella.exe` is a windowed program: run directly, the terminal does not wait for it, the output arrives after the prompt and the exit code is lost. The `.cmd` file waits, returns the code and starts Chromium without its sandbox, which does not start inside the sandbox of some AI agents (Codex). **AI tools…** in the app already shows this command. The portable version has no `.cmd` file.
- Codex on Windows runs commands in a sandbox that only reads the folders open to sandboxed apps. Since 1.2.0-beta.9 the installer opens Stella's folder for reading and execution, so nothing is needed. With an earlier version, or if the error _Sandboxed processes cannot read …_ still appears, approve the execution outside the sandbox when Codex asks, or grant the permission by hand from a normal PowerShell: `icacls "$env:LOCALAPPDATA\Programs\stella" /grant "*S-1-15-2-1:(OI)(CI)(RX)" /T` (`*S-1-15-2-1` is the group ALL APPLICATION PACKAGES, with a different name in translated versions of Windows).
- Without the desktop app (for example with the web version only): every release publishes `stella-cli-<version>.tgz`, the command alone, which installs with Node.js 20 or later: `npm install -g https://github.com/lucadj77/stella/releases/download/v<version>/stella-cli-<version>.tgz`. The command becomes `stella`; on install it downloads Electron, which draws the cards (about 250 MB in all). It is built by `scripts/cli-package.mjs`, in the `cli` job of `.github/workflows/build.yml`. Usually there is no need to install it by hand: the skill (see below) proposes it, installs the latest official version (`releases/latest`) and moves to the betas only if the installed package is already a beta or if you ask.
- From the source code: once `npm run build`, then `npm run stella -- info <project>` or `node bin/stella.mjs info <project>`. With `npm link` the command becomes `stella` in every folder.

## Working with the app open

The app and an agent must not edit the same project at the same time, otherwise a save by one erases the changes of the other. That is why the agent opens and closes its work with `begin` and `end`, as the skill asks:

- the open app writes the file `.stella-app` in the project folder, with its process and whether it has unsaved changes;
- `begin` refuses to start (exit code 3) if the app has unsaved changes: the agent asks to save and stops. Otherwise it writes the file `.stella-ai`;
- while `.stella-ai` exists the app shows a notice and cannot be used. It checks every second;
- `end` deletes `.stella-ai`: the app unlocks and reloads the project by itself.

If the agent stops without `end`, the notice has **Unlock now**. `set-rows`, `pull-sheets`, `rename-set` and `rename-template` also refuse on their own (exit code 2) if the app has unsaved changes, and also if the app is open on the project without a `begin`: otherwise the app's next save would erase their changes. The two files start with a dot, so they stay out of the backups; a `.stella-app` left by an app that closed badly does not count, because its process is gone. On a disk shared between several computers the app's file counts only if it was updated in the last 5 minutes (the app rewrites it every 30 seconds).

If `stella.json` has `"dataReadOnly": true` (the data file is read-only, set in the app), `set-rows` and `pull-sheets` refuse, and `rename-set` renames the set but not the sheet.

The backup made by `set-rows`, `pull-sheets`, `rename-set` and `rename-template` goes to the same folder as the app's automatic backups, with the same settings (folder and number of backups to keep).

## Skill for the agents

The skill is in [skill/stella/SKILL.md](../skill/stella/SKILL.md), in English: it explains the project format, the markup, the formulas and the way of working (`info`, then the changes, then `check` and `render` to verify). The placeholder `{{STELLA_COMMAND}}` stands for how to run the command.

In the app, **AI tools…** (in the ⚙ menu of every screen) shows the skill with this computer's command already filled in. You can copy and paste it into the agent, asking it to install it, or save it as a file in `<folder>/stella/SKILL.md`; Claude Code reads skills from `~/.claude/skills` or from `.claude/skills` inside a project. Only the instructions around the skill are translated.

The skill carries the Stella version it is written for (`{{STELLA_VERSION}}`, filled in by **AI tools…**). At the start of the work it asks the agent to find the command (the desktop app in the usual paths, then `stella` in the PATH), to read its version with `stella version`, to propose installing the `stella-cli` package if it finds nothing (and Node.js before, if missing), to update the package when a newer release is out (the desktop app updates by itself) and to replace itself with the skill of the same version as the command, taken from the tag on GitHub. In the web version **AI tools…** shows the skill without a command, which the agent finds this way.

When the project format changes, the skill must be updated too.
