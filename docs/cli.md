# Comando stella e strumenti per gli agenti IA

_English: [cli.en.md](cli.en.md)._

Il comando `stella` permette a un agente IA (Claude Code, Codex, Cursor…) o a uno script di lavorare su un progetto senza aprire l'app: legge i dati, segnala i problemi e disegna le carte in PNG. È lo stesso programma dell'app avviato con `--cli`: nessuna finestra, stesso rendering delle esportazioni.

## Comandi

| Comando                                                                                                           | Cosa fa                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `info <progetto>`                                                                                                 | set, template e livelli, variabili, stili, asset, profili di esportazione                                                                                                                                                                                                                                                                                        |
| `check <progetto> [--set S] [--lang L]`                                                                           | problemi di ogni carta (immagini o font mancanti, variabili sconosciute, errori di markup e formule) e, senza `--set`, dei documenti; esce con 1 se ce ne sono. Elenca anche i testi non tradotti come avvisi, che non cambiano il codice di uscita: in L o, senza `--lang`, in tutte le lingue oltre la principale; con `--lang` lega le carte in quella lingua |
| `check-data <progetto>`                                                                                           | come viene letto il file dei dati: per ogni foglio i set che lo usano, le colonne che i loro template leggono e il foglio non ha, e le anomalie (titolo sopra le intestazioni, righe vuote, celle unite, errori, formule senza risultato); è lo stesso controllo di **Controlla file dati** nell'app                                                             |
| `template <progetto> <nome>`                                                                                      | livelli del template (per un derivato, già risolti, con il base e le differenze); con `--json` il template completo                                                                                                                                                                                                                                              |
| `rows <progetto> <set> [--json\|--csv]`                                                                           | righe del set, separate da tab se non si indica altro                                                                                                                                                                                                                                                                                                            |
| `set-rows <progetto> <set> <file.json\|file.csv>`                                                                 | sostituisce le righe del set, dopo aver fatto un backup del progetto                                                                                                                                                                                                                                                                                             |
| `pull-sheets <progetto> [<link>]`                                                                                 | sostituisce i dati dei set con le schede con lo stesso nome di un foglio Google condiviso con il link (senza link usa quello salvato nel progetto; un link nuovo si salva), dopo aver fatto un backup del progetto                                                                                                                                               |
| `rename-set <progetto> <set> <nome>`                                                                              | rinomina il set, il suo foglio nel file dei dati e i profili di esportazione che lo scelgono, dopo un backup                                                                                                                                                                                                                                                     |
| `rename-template <progetto> <template> <nome>`                                                                    | rinomina il template e il suo file; set, derivati e colonna `template` delle carte seguono il nome nuovo; prima fa un backup                                                                                                                                                                                                                                     |
| `render <progetto> [--set S] [--card 1,3,5-7] [--side front\|back\|both] [--dpi 150] [--out cartella] [--lang L]` | disegna le carte in PNG, di base in `export/stella-render/<set>/<n>.png`; con `--lang` una lingua del progetto, in `export/stella-render/<lingua>/`                                                                                                                                                                                                              |
| `export <progetto> --profile NOME [--lang L\|all]`                                                                | esegue un profilo di esportazione salvato nel progetto; `--lang` sceglie una lingua (le altre lingue vanno nella sottocartella con il loro codice) o `all` per tutte                                                                                                                                                                                             |
| `new <nome> <cartella>`                                                                                           | crea un progetto vuoto                                                                                                                                                                                                                                                                                                                                           |
| `notes <progetto> [<nome>]`                                                                                       | note del progetto (`notes/*.md`), tutte o una; l'agente le scrive come file Markdown in `notes/`                                                                                                                                                                                                                                                                 |
| `docs <progetto> [<nome>]`                                                                                        | documenti del progetto (`docs/*.md`: regolamento, sell sheet, appendici), tutti o uno, con i loro problemi (carte o immagini che non si trovano); l'agente li scrive come file Markdown in `docs/`                                                                                                                                                               |
| `export-doc <progetto> [<nome>] [--format pdf\|html\|docx\|md] [--out cartella] [--lang L]`                       | esporta i documenti, tutti o uno, come **Esporta documento…** nell'app: PDF (di base), HTML autonomo, Word (`.docx`) o Markdown con le carte in PNG, di base in `export/docs/`; avvisa dei riferimenti che non si trovano; `--lang` disegna le carte in quella lingua al posto di `language` del documento                                                       |
| `stats <progetto> <set> [--column C]`                                                                             | quante carte hanno ogni valore di ogni colonna (o di una), con somma, media, minimo e massimo delle colonne numeriche                                                                                                                                                                                                                                            |
| `begin <progetto> [--note testo]`                                                                                 | inizio del lavoro di un'IA: esce con 3 se l'app ha modifiche non salvate nel progetto, altrimenti l'app si blocca                                                                                                                                                                                                                                                |
| `end <progetto>`                                                                                                  | fine del lavoro: l'app si sblocca e ricarica il progetto                                                                                                                                                                                                                                                                                                         |
| `version`                                                                                                         | la versione del comando (anche `--version`): la skill la confronta con la sua e con l'ultima release                                                                                                                                                                                                                                                             |

`info`, `check`, `template`, `stats`, `notes` e `docs` accettano `--json`. `stella --help` elenca i comandi.

## Come si lancia

- App installata: `"<percorso del programma>" --cli <comando>`. Su Mac il programma è dentro il pacchetto, per esempio `"/Applications/Stella.app/Contents/MacOS/Stella" --cli info ~/Documents/Stella/Prova`.
- Su Windows, con l'app installata, si usa `stella-cli.cmd`, che sta accanto a `stella.exe` (di solito in `%LOCALAPPDATA%\Programs\stella`): per esempio `& "$env:LOCALAPPDATA\Programs\stella\stella-cli.cmd" info "D:\Giochi\Prova"` in PowerShell. `stella.exe` è un programma a finestre: lanciato direttamente il terminale non ne aspetta la fine, l'output arriva dopo il prompt e il codice di uscita si perde. Il file `.cmd` aspetta, restituisce il codice e avvia Chromium senza la sua sandbox, che non parte dentro quella di alcuni agenti IA (Codex). **Strumenti IA…** nell'app mostra già questo comando. La versione portable non ha il file `.cmd`.
- Codex su Windows esegue i comandi in una sandbox che legge solo le cartelle aperte alle app in sandbox. Dalla 1.2.0-beta.9 l'installer apre la cartella di Stella in sola lettura ed esecuzione, quindi non serve fare niente. Con una versione precedente, o se compare ancora l'errore _Sandboxed processes cannot read …_, si approva l'esecuzione fuori dalla sandbox quando Codex la chiede, oppure si dà il permesso a mano, da una PowerShell normale: `icacls "$env:LOCALAPPDATA\Programs\stella" /grant "*S-1-15-2-1:(OI)(CI)(RX)" /T` (`*S-1-15-2-1` è il gruppo ALL APPLICATION PACKAGES, con un nome diverso nelle versioni tradotte di Windows).
- Senza l'app desktop (per esempio con la sola versione web): ogni release pubblica `stella-cli-<versione>.tgz`, il solo comando, che si installa con Node.js 20 o successivo: `npm install -g https://github.com/lucadj77/stella/releases/download/v<versione>/stella-cli-<versione>.tgz`. Il comando diventa `stella`; all'installazione scarica Electron, con cui disegna le carte (circa 250 MB in tutto). Lo prepara `scripts/cli-package.mjs`, nel job `cli` di `.github/workflows/build.yml`. Di solito non serve installarlo a mano: lo propone la skill (vedi sotto), che installa l'ultima versione ufficiale (`releases/latest`) e passa alle beta solo se il pacchetto installato è già una beta o se lo chiedi.
- Dal codice: una volta `npm run build`, poi `npm run stella -- info <progetto>` oppure `node bin/stella.mjs info <progetto>`. Con `npm link` il comando diventa `stella` in ogni cartella.

## Lavorare con l'app aperta

L'app e un agente non devono modificare lo stesso progetto insieme, altrimenti un salvataggio dell'uno cancella le modifiche dell'altro. Per questo l'agente apre e chiude il suo lavoro con `begin` ed `end`, come chiede la skill:

- l'app aperta scrive nella cartella del progetto il file `.stella-app`, con il suo processo e se ha modifiche non salvate;
- `begin` rifiuta di partire (codice di uscita 3) se l'app ha modifiche non salvate: l'agente chiede di salvare e si ferma. Altrimenti scrive il file `.stella-ai`;
- finché c'è `.stella-ai` l'app mostra un avviso e non si usa. Si controlla ogni secondo;
- `end` cancella `.stella-ai`: l'app si sblocca e ricarica il progetto da sola.

Se l'agente si ferma senza `end`, nell'avviso c'è **Sblocca ora**. `set-rows`, `pull-sheets`, `rename-set` e `rename-template` rifiutano anche da soli (codice di uscita 2) se l'app ha modifiche non salvate, e anche se l'app è aperta sul progetto senza che sia stato fatto `begin`: altrimenti il prossimo salvataggio dell'app cancellerebbe le loro modifiche. I due file iniziano con il punto, quindi restano fuori dai backup; un `.stella-app` lasciato da un'app chiusa male non conta, perché il suo processo non c'è più. Su un disco condiviso tra più computer il file dell'app conta solo se è stato aggiornato negli ultimi 5 minuti (l'app lo riscrive ogni 30 secondi).

Se in `stella.json` c'è `"dataReadOnly": true` (il file dei dati in sola lettura, impostato nell'app), `set-rows` e `pull-sheets` rifiutano, e `rename-set` rinomina il set ma non il foglio.

Il backup fatto da `set-rows`, `pull-sheets`, `rename-set` e `rename-template` va nella stessa cartella dei backup automatici dell'app, con le stesse impostazioni (cartella e numero di backup da tenere).

## Skill per gli agenti

La skill è in [skill/stella/SKILL.md](../skill/stella/SKILL.md), in inglese: spiega il formato del progetto, il markup, le formule e il modo di lavorare (`info`, poi le modifiche, poi `check` e `render` per controllare). Spiega anche come aggiungere un profilo di esportazione a un progetto che non ne ha (per eseguirlo con `export --profile`) e come prendere icone da Iconify, annotando origine e licenza in `assets/sources.json` come fa **Importa icone** nell'app, così i crediti restano completi. Il segnaposto `{{STELLA_COMMAND}}` indica come lanciare il comando.

Nell'app **Strumenti IA…** (nel menu ⚙ di ogni schermata) mostra la skill con il comando di questo computer già inserito. Si può copiare e incollare nell'agente, chiedendogli di installarla, oppure salvare come file in `<cartella>/stella/SKILL.md`; Claude Code legge le skill da `~/.claude/skills` o da `.claude/skills` dentro un progetto. Solo le istruzioni intorno alla skill sono tradotte.

La skill porta la versione di Stella per cui è scritta (`{{STELLA_VERSION}}`, inserita da **Strumenti IA…**). All'inizio del lavoro chiede all'agente di trovare il comando (l'app desktop nei percorsi abituali, poi `stella` nel PATH), di leggerne la versione con `stella version`, di proporre l'installazione del pacchetto `stella-cli` se non trova niente (e prima di Node.js, se manca), di aggiornare il pacchetto quando esce una release più recente (l'app desktop invece si aggiorna da sola) e di sostituirsi con la skill della stessa versione del comando, presa dal tag su GitHub. Nella versione web **Strumenti IA…** mostra la skill senza comando, che l'agente trova così.

Quando cambia il formato del progetto va aggiornata anche la skill.
